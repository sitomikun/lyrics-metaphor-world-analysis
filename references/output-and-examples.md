# 報告形式と境界例

## 標準の報告

依頼の深さに合わせ、以下の順序を保つ。理論の説明を長い前置きにせず、曲の語句と関係を中心に書く。短い入力に空の見出しや不要な表を増やさない。

1. **対象と前提**：分析版、区分の扱い、重大な不明点。外部照合していなければ公式版確認済みとはしない。
2. **主要表現の精読**：原文の位置、比喩等の判定理由、解釈、必要な留保。慣用比喩も含め全文確認するが、公開表は意味に関わる表現を中心にする。
3. **語彙と歌詞世界**：関連する語群、概念対応、人物・時空・現実性、競合する像や視点。ブレンドの説明は必要な場合だけ追加。
4. **セクションの比較**：全区間を追跡可能にし、重要な接続・回帰・差分を詳述。語句の分析結果を参照する。
5. **全体解釈と未確定点**：変化と維持、終わり方、結論を左右する別解と根拠の違い。
6. **曲間比較**：複数曲の場合のみ。作詞への応用は依頼がある場合のみ別項。

引用がない要約文にも位置を付けられる。根拠メモをそのまま大量に出力するより、重要な主張を検証できる代表例と位置を示す。細密な語句一覧は必要時に付す。

判定や解釈の留保は、具体的に何が未確定かを書く。「かもしれない」をすべての文につけるだけでは不十分。本文に明示された関係は明確に述べ、複数の読みが残る部分を区別する。

## 曲番号と歌詞行番号

報告の位置表示は次の規則に統一する。

- **曲番号**：1回の投稿で提供された順に `[Song 1]`、`[Song 2]`…とする。略記は `[S1]`、`[S2]`…。複数添付は投稿の添付順、各添付内は曲の掲載順で通し番号を付ける。元資料の `[Song 8]` などは出典情報としてのみ保持する。同名曲・同じ本文も、別の掲載分なら勝手に統合しない。
- **範囲**：その投稿で採用する歌詞全体を先に番号付けする。小分けの分析でも番号を振り直さない。次の投稿では新たに1から数える。訂正・差し替えの依頼は対象曲との対応を示し、採用する版を明記する。
- **行番号**：各曲の最初のセクションタグ直下からL1とする。本文範囲内ではタグだけの行を除き、空白行も含めて物理的な行ごとにL2、L3…と続ける。最初のタグの直後が空白行なら、その空白行がL1。空文字の行、スペース・タブ・全角空白だけの行をいずれも1行として数え、連続する空白行を圧縮しない。セクションが替わっても連番を維持し、曲が替わったらL1から始める。表示画面の自動折り返しや文の個数では数えない。
- **本文以外**：曲名、歌詞紹介行、クレジット、URL、曲間の区切り等は本文範囲から外す。タグ名だけで本文範囲を自動推測しない。歌詞とタグが同じ行にある場合は、その歌詞を1行として数える。実際に記された反復行は毎回数え、反復の省略記号から存在しない行を展開しない。
- **タグがない場合**：最初のタグより前に歌詞があるときは、確認した本文範囲の先頭からL1を始め、その範囲内の空白行も数える。全体が無タグでも同様。無タグの末尾も落とさない。最初のタグより前にある曲情報と、その周囲の空白行は数えない。
- **歌詞のない区間**：Interludeなどにも空白行があれば番号を付け、「歌詞なし（L22は空白行）」等と示す。原文に本文行がまったくない区間だけは番号を消費せず、「歌詞なし（L7とL8の間）」「歌詞なし（L1の前）」等と位置を示す。番号付きの空白行があることと、歌詞の言葉があることを分け、空白から出来事・心理・演奏時間を推測しない。連続する空区間は原タグ順と区間IDで区別する。
- **表記**：曲見出しは `[Song 1] 曲名`、位置は `[S1] L3–4`。同じ曲の見出し内ではL3–4と省略できるが、曲間比較では曲番号を添える。略記のSは曲番号に使い、区間IDは `S1-SEC01` 等として混同を避ける。
- **照合と末尾**：元ファイルの行番号は内部に別途保持する。読者向けのL番号を元ファイル行番号と混ぜない。物理行が必要な場合は「元ファイル第136行」と明記する。本文として採用した末尾の空白行も数えるが、ファイル末尾の改行コードだけを新たな空白行にしない。例えば `本文\n` は1行、`本文\n\n` は末尾の空白を含む2行。改行・空白行・版の変更で番号も変わるため、採用した原文を固定し、旧方式で作った索引は再作成する。

例えばVerse 1に2行の歌詞と1行の空白、次のPre-Chorusに2行の歌詞と1行の空白、その次のChorusに3行の歌詞があれば、歌詞の言葉がある行は順にL1–2、L4–5、L7–9となる。区間範囲は区間末尾の空白も含み、Verse 1はL1–3、Pre-ChorusはL4–6。さらに空白行が増えれば、その後の番号も増える。

## 最小の記述例

以下はこのガイドのために作成した架空の短文。特定の作品の分析結果ではなく、全文の文脈によって判断が変わり得る境界例である。

| 架空の表現 | 支持できる観察 | 追加根拠なしに確定しないこと |
|---|---|---|
| 海辺の売店で切符を買う | 場所、物、行為を構成している | 海は解放、切符は人生の転機 |
| 予定がほどけて床に散った | 「予定」をほどけたり散ったりする物として捉える読み | 何の物質か、人生全体の崩壊か |
| 君も兄のように背が高い | 同じ性質についての比較 | 「ように」があるので必ず比喩 |
| 雨が降るようだ | 推量として読める | 直喩 |
| ここでは椅子が歩く。それが町の決まりだ | 作品内の字義的な設定として成立し得る | 現実に不可能なので特定の社会問題の比喩 |
| 渡れたら、向こうで名前を呼びたい | 条件と願望、未実現の行為 | 既に渡り終えた、相手と再会した |
| 「出ていけ」と言った声を、今は悔やむ | 過去の発話と現在の評価が異なる | 現在も相手へ退去を命じている |
| 地図の外へ出た。窓はまだ閉じている | 移動の表現と閉じた状態の並置 | 最後には全面的な解放に到達した |

語句が変わらない反復の比較には、次の架空例を使える。

- 区間1「扉は閉じたまま」。区間2で誰も訪れず、区間3も同句なら、閉鎖の継続がまず候補。
- 区間1が同句、区間2で「内側から鍵をかけた」と分かり、区間3も同句なら、外から閉ざされたという初期の推測は修正され得る。ただし最初から閉鎖の原因は明示されていない。

後続情報が変更するのは、本文で明示された事実なのか、読者が仮に補った読みなのかも区別する。

## 任意の本文索引ツール

UTF-8テキストの原文行・タグ・明示区切りと、確認済みの曲内行番号を記録するときに使用する。Python 3標準ライブラリのみ。実行時は利用可能なPythonの実パスを使い、例の入力名を実在ファイルに置き換える。

```text
python scripts/index_lyrics.py lyrics.txt --output work/lyrics-index.json
python scripts/index_lyrics.py corpus.txt --song-map work/song-map.json --output work/lyrics-index.json
python scripts/index_lyrics.py first.txt second.txt --song-map work/song-map.json --output work/lyrics-index.json
```

パスはスキルフォルダを基準に解決するか、スクリプトの絶対パスを使う。最初の例は原文索引だけを作る。`--song-map` を省くと `songs` は空で、曲内行番号は未設定となる。この場合に `source_line` を報告のL番号へ流用しない。原文ブロックの補助分割が必要なら、入力を見て選んだ `--split-pattern "={8,}"` 等を追加できる。原文ブロックは曲数の確定ではない。

曲内行番号を作る場合は、入力本文を読んで各曲の範囲を確定し、次の形式で `song-map.json` を用意する。

```json
{"songs": [
  {"input_id": "F001", "title": "曲A", "source_line_range": [4, 30]},
  {"input_id": "F001", "title": "曲B", "source_line_range": [45, 70]}
]}
```

`input_id` はコマンドに渡したファイル順のF001、F002…で、投稿の添付順にそろえる。`source_line_range` は元ファイルの物理行を使った両端を含む範囲であり、上の数値は例。最初の本当のセクションタグ（タグ前にも歌詞があればその本文の先頭）から、末尾の空白行も含む採用本文の終端までを指定する。曲紹介や前後のメタデータ、曲間区切りは入れない。本文中や本文末尾の空白を自動で削らず、曲間整理用の余白との境界が不明なら採用範囲を記録する。`title` は任意で、歌詞として数えられない。入力順・曲順に全曲を列挙し、番号はスクリプトに割り当てさせる。順序逆転、重複範囲、範囲外、未知の入力IDはエラーになる。

JSONの `songs` が報告用の索引になる。`song_label`／`short_label`、`lines[].lyric_line`、`sections[].lyric_line_range` を使う。`lyric_line_count` と区間範囲は空白を含む番号付きの行数・範囲であり、言葉がある行数ではない。`is_blank`、`content_line_count`、`blank_line_count`、`has_lyrics` で両者を区別する。空白1行だけの区間は1行の範囲を持ち、`has_lyrics` はfalse。本文行がまったくない区間だけが範囲null・行数0となり、`after_lyric_line`／`before_lyric_line` が前後の番号付き行を示す。`lines[].source_line` は元ファイルとの照合用で、原文の文字や改行は変更しない。原文の `inputs`、`blocks` とその物理行範囲は別に保持する。

索引が自動認識するのは、単独行の角括弧 `[tag]` 形式である。曲名もこの形になり得るため、本文範囲の確認は分析者が行う。別形式のタグや途中に混じる曲情報がある場合は、原文を保持した手動の対応表で補い、メタデータを歌詞に数えない。本文にタグがない場合の意味区間も別途設定する。索引は比喩、話者、音楽形式、区間機能を判定しない。

原文ファイルを上書きせず、作業先へ出力する。本文を外部へ送信する機能はない。同一本文の検出は完全一致の補助であり、差分の解釈や意味の同一性は人手で確認する。

`preamble`には曲名やクレジットが含まれることがある。索引の範囲名を歌詞かどうかの判定に使わない。`body_text`が空白・改行だけなら歌詞なしとして扱う。採用本文の空白行は位置の行番号には含めるが、空白だけの本文を反復歌詞の候補には数えない。
